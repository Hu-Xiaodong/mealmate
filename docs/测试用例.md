## 1. 使用说明

### 1.1 维护规则

1. 本文件是唯一测试用例文件，不按模块拆分，不新建第二份。
2. 每次功能变更，至少完成三件事：
   - 新增功能：补充对应用例；
   - 修改功能：修改受影响的旧用例，而不是只追加新用例；
   - 删除功能：删除对应用例，避免执行时被过期用例误导。
3. 用例编号一经使用不再复用。删除用例后编号作废，新用例取新编号。
4. 每次执行后更新第 8 节“执行记录”；发现缺陷登记到第 9 节。
5. 已知缺陷不隐藏：正确结果写在用例里，同时在“已知问题”中说明当前实际表现。

### 1.2 优先级定义

| 优先级 | 含义 | 使用场景 |
| --- | --- | --- |
| P0 | 阻断级 | 主流程不可用、数据错误、安全问题。每次回归必须执行 |
| P1 | 重要级 | 主要功能的异常分支、权限、空状态、边界值 |
| P2 | 一般级 | 展示细节、兼容性、极端参数 |

### 1.3 执行结果标记

| 标记 | 含义 |
| --- | --- |
| 通过 | 实际结果与预期一致 |
| 失败 | 实际结果与预期不一致，必须登记缺陷 |
| 阻塞 | 前置条件不满足，无法执行 |
| 未执行 | 本轮未安排执行 |

| 缺陷编号 | 关联用例 | 严重级别 | 描述 | 当前状态 |
| --- | --- | --- | --- | --- |
| BUG-001 | A-PUB-013、A-PUB-014、API-POST-014 | 高 | 口味标签前后端枚举不一致：前端选项为“清淡、正常、香辣、酸甜、咸鲜、油炸、烧烤、汤羹、面食”；后端只接受“清淡、重口下饭、微辣、特辣、酸甜、咸鲜、油炸、烧烤、汤羹、面食”。选择“正常”或“香辣”发布时后端返回 422，同时用户无法选择“重口下饭、微辣、特辣”。 | 已修复（2026-11-20）：口味标签改为数据库字典表 `taste_tags`，接口 `GET /taste-tags` 下发；后端在发布、草稿、改草稿、草稿发布四个入口按数据库“已启用”标签校验，未知或停用标签返回 `TASTE_TAG_INVALID`。 |

### 3.2 当前实现与 PRD 的差异（不作为缺陷）

以下能力按当前实现验收，避免把“未实现”误判成“回归失败”：

1. **短信验证码**：当前只使用开发固定验证码，不接真实短信通道；生产环境配置会强制关闭固定验证码。
2. **详情页图片**：只支持手动左右滑动，没有自动轮播。
3. **AI 能力**：后台可以配置多个模型，同一用途同时只启用一个；无论使用模型还是本地规则，推荐卡片都只来自已发布菜谱，模型返回不存在的编号会被丢弃。未启用模型或启用模型调用失败时自动回退本地规则，接口不再返回 503；每日次数限制可通过 `AI_DAILY_LIMIT_ENABLED` 暂停。
4. **地图能力**：发布页通过全屏静态地图页搜索并选择店铺，地图不能手指拖动，只提供缩放与回到当前位置；详情页展示静态地图并拉起腾讯地图导航；没有内嵌可交互地图。
5. **管理后台**：已具备数据看板、饭帖审核（含批量审核）、菜谱管理、口味标签维护、模型配置、AI 调用日志、知识库、用户管理（含“查看发布”）、管理员与角色、审计日志十个模块。
6. **知识库（RAG 切片与嵌入）**：只支持后台上传 UTF-8 的 `.md` / `.txt` 文档；上传只做切片，文档列表同一行显示待索引切片数量与参数，运营点“去新建索引”确认后才生成向量。上传时可以同时选择 Markdown 引用的图片（JPG / PNG / WebP），后端按文件名匹配、保存到文档目录并把地址改写为 `/media/...`，切片预览直接显示图片；生成向量前会自动去掉图片标记。检索测试按余弦相似度返回片段，嵌入模型不可用时自动降级为关键词检索并显示提示；PDF 解析、异步任务进程、把检索结果接入 App 问答留到后续阶段，本版不测。
7. **小程序端**：按项目规则暂停开发，不在本用例范围。
8. **AI 入口**：首页、菜谱列表、饭帖详情三处入口共用同一个 AI 能力；后台启用模型后走真实模型，未启用或启用模型调用失败时自动走本地规则推荐。
9. **埋点**：客户端匿名批量上报，服务端只做幂等入库与看板聚合，不参与业务判定；报表口径以管理后台“数据看板”为准。
10. **AI 对话历史**：移动端采用“本地为主 + 登录后合并上云”。游客记录只在本机保留 7 天；登录用户本地保留 30 天、服务端保留 30 天。每次请求只带最近 8 条消息，历史达到模型上下文窗口 60% 时把窗口外旧消息压缩成摘要。Redis 存放最近 30 分钟会话并滑动过期；本地未启动 Redis 时，登录用户自动降级读数据库，游客依赖客户端随请求带来的最近 8 条历史。不提供删除历史入口，历史由超时自动清理。
11. PRD 中尚未在代码中落地的其他能力（例如真实短信、消息通知等），本版不测；实现后再补用例。

### 3.3 执行约定

1. 登录、点赞、收藏、发布等写操作使用独立测试账号，避免污染演示数据。
2. 测试“待审核”流程前，先把 `AUTO_PUBLISH_POSTS` 改为 `false` 并重启后端；测试“直接发布”流程时改回 `true`。
3. 测试管理后台权限分离时，必须使用只有部分权限的管理员账号，不能只用超级管理员。
4. 每个用例执行后记录实际结果；失败用例必须附请求编号（`requestId`）或截图说明。

## 5. 后端接口测试用例

### 5.1 通用约定

| 项目 | 说明 |
| --- | --- |
| 基础地址 | `http://127.0.0.1:8000/api/v1` |
| 成功响应 | HTTP 200，`code` 为 `0`，业务数据在 `data` |
| 失败响应 | HTTP 4xx 或 5xx，`code` 为业务错误码，`message` 可直接展示 |
| 登录凭证 | 请求头 `Authorization: Bearer <token>` |
| 字段命名 | 请求与响应统一使用小驼峰（例如 `imageAssetIds`） |
| 请求编号 | 响应中的 `requestId` 用于排查日志，失败用例必须记录 |
