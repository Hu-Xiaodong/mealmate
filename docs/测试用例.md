## 1. 使用说明

### 1.1 维护规则

1. 本文件是唯一测试用例文件，不按模块拆分，不新建第二份。
2. 每次功能变更，至少完成三件事：
   - 新增功能：补充对应用例；
   - 修改功能：修改受影响的旧用例，而不是只追加新用例；
   - 删除功能：删除对应用例，避免执行时被过期用例误导。
3. 用例编号一经使用不再复用。删除用例后编号作废，新用例取新编号。
4. 每次执行后更新第 8 节“执行记录”；发现缺陷登记到第 9 节。
5. 已知缺陷不隐藏：正确结果写在用例里，同时在“已知问题”中说明当前实际表现。

### 1.2 优先级定义

| 优先级 | 含义 | 使用场景 |
| --- | --- | --- |
| P0 | 阻断级 | 主流程不可用、数据错误、安全问题。每次回归必须执行 |
| P1 | 重要级 | 主要功能的异常分支、权限、空状态、边界值 |
| P2 | 一般级 | 展示细节、兼容性、极端参数 |

### 1.3 执行结果标记

| 标记 | 含义 |
| --- | --- |
| 通过 | 实际结果与预期一致 |
| 失败 | 实际结果与预期不一致，必须登记缺陷 |
| 阻塞 | 前置条件不满足，无法执行 |
| 未执行 | 本轮未安排执行 |

## 3. 已知问题与暂不测试范围

### 3.1 已知缺陷

| 缺陷编号 | 关联用例 | 严重级别 | 描述 | 当前状态 |
| --- | --- | --- | --- | --- |
| BUG-001 | A-PUB-013、A-PUB-014、API-POST-014 | 高 | 口味标签前后端枚举不一致：前端选项为“清淡、正常、香辣、酸甜、咸鲜、油炸、烧烤、汤羹、面食”；后端只接受“清淡、重口下饭、微辣、特辣、酸甜、咸鲜、油炸、烧烤、汤羹、面食”。选择“正常”或“香辣”发布时后端返回 422，同时用户无法选择“重口下饭、微辣、特辣”。 | 已修复（2026-11-20）：口味标签改为数据库字典表 `taste_tags`，接口 `GET /taste-tags` 下发；后端在发布、草稿、改草稿、草稿发布四个入口按数据库“已启用”标签校验，未知或停用标签返回 `TASTE_TAG_INVALID`。 |

### 3.2 当前实现与 PRD 的差异（不作为缺陷）

以下能力按当前实现验收，避免把“未实现”误判成“回归失败”：

1. **短信验证码**：当前只使用开发固定验证码，不接真实短信通道；生产环境配置会强制关闭固定验证码。
2. **详情页图片**：只支持手动左右滑动，没有自动轮播。
3. **AI 能力**：当前是本地规则推荐器，只从已发布菜谱中筛选，不是大模型自由生成；当 `AI_PROVIDER` 不是 `mock` 时接口返回 503。
4. **地图能力**：发布页通过全屏静态地图页搜索并选择店铺，地图不能手指拖动，只提供缩放与回到当前位置；详情页展示静态地图并拉起腾讯地图导航；没有内嵌可交互地图。
5. **管理后台**：只有“饭帖审核、用户管理、审计日志”三个业务模块，没有仪表盘。
6. **小程序端**：按项目规则暂停开发，不在本用例范围。
7. PRD 中尚未在代码中落地的其他能力（例如真实短信、消息通知等），本版不测；实现后再补用例。

### 3.3 执行约定

1. 登录、点赞、收藏、发布等写操作使用独立测试账号，避免污染演示数据。
2. 测试“待审核”流程前，先把 `AUTO_PUBLISH_POSTS` 改为 `false` 并重启后端；测试“直接发布”流程时改回 `true`。
3. 测试管理后台权限分离时，必须使用只有部分权限的管理员账号，不能只用超级管理员。
4. 每个用例执行后记录实际结果；失败用例必须附请求编号（`requestId`）或截图说明。
